audit from a model arm. A formal SIS audit of run-defense Boom%/Bust%, pass
rush, and catchable/on-target fields can run while the ledger is active. Any
model/cache arm licensed by that audit queues behind the ledger.

## Necessary precision on SIS tail evidence

SIS tail-shape data are not wholly untested. The already-completed opponent
pass-tail arm appended pass-defense Boom%, Bust%, and pressure rate. It passed
the score-free gate and its five-seed exact-80 comparison selected treatment,
adding two >=220 and three >=200 seed-week maxima. That evidence is preserved;
it is neither a central-tendency failure nor a reason to repeat the same arm.

The amendment's genuinely open candidate is narrower: opponent **run-defense**
Boom%/Bust% for RBs. The prior RB Points-Saved protocol explicitly prohibited
adding Boom%/Bust% after its failure, so a new run-tail test cannot be presented
as untouched confirmatory evidence. It may proceed only if the formal
outcome-blind audit passes, and then only as a separately frozen,
`adaptive_retrospective=true` arm whose rationale, support, season coverage,
feature block, control reproduction, gate, and relationship to the earlier
prohibition are disclosed before model output.

2. In parallel, run only read-only/outcome-blind SIS support and redundancy

4. If the formal SIS run-tail audit passes, decide and freeze the explicitly
   adaptive run-defense Boom%/Bust% arm before any model output; run it only

G2, or any other terminal mechanism. It prevents the forensic exhaustion
certificate from claiming closure while a mechanically unadjudicated mechanism
