# Fixed-K current-pool retrieval: guarded 220-coverage replacements

September 19, frozen before comparing replacements. This is an outcome-free diagnostic on the same archived Thursday D6400 candidate pool and reproduced raw-DEMAX K97 book. It asks whether new candidates can improve modeled 220+ coverage at fixed membership count while preserving the existing model objectives. It is not an actual-outcome validation or a switch to a 220-only serving objective.

Input identities and arithmetic are unchanged from the [current-selector diagnostic](2026-09-18-week2-current-selector-diagnostic-protocol.md): 435 players, 6400 unique rosters, two float32 10,000-world selection banks; float32 roster sums followed by float64 metric reductions. Read only frame.id and candidate.players, plus the four hash-pinned objects and existing 97 candidate indices. GLOBAL proxy uses the same frozen 48-value historical registry and bandwidth 8. No current actuals or bank 991 reads.

Start from the original diagnostic K97 book, not the allocation-exchanged version. Milly row 1 remains fixed. Consider replacing exactly one row 2–97 with a currently unselected candidate. Require whole-book P220 nondecreasing in EACH component and strictly increasing in the equal mixture. Rank proposed pairs by largest integer total of additional covered worlds across both components, then smallest row, then smallest candidate index.

For every proposed pair, require nondecreasing Emax, GLOBAL proxy and P220 separately in EACH component for every affected protected set: whole K97 book; prefixes 1/10/20/30/40/80/90/97; and the disjoint actual contest block containing the replaced row. The other blocks and unaffected prefixes are unchanged automatically. Nondecrease tolerance is 1e-12 for reductions; threshold hits use exact >=220 under original summation, with no count tolerance. Accept the first passing pair in the declared order. Repeat at most THREE accepted replacements, retaining all selected candidate identities and positions between steps.

This search deliberately differs from E0d: current D6400 population, K97, raw-DEMAX starting book, replacement from the external pool, 220-coverage ranking and simultaneous model/component/block/prefix guards. It does not reopen a prior result under the same implementation/information/objective/budget. The strong guard may leave no candidate. Zero is reported without relaxing constraints. Positive results are candidates for independent review and independent-bank/final-book checks, not automatic entry changes.

Checks: identity hashes; original 97 unique rosters; fixture bit-packed coverage deltas equal direct before/after counts including unique lost coverage and no coverage; each accepted replacement's direct recomputed metrics match the fast guard; final no-harm vs ORIGINAL book for every protected set; row 1 and book size fixed. Exact accepted rosters/indices, before/after metrics and rejected-pair stage counts are retained. No claim that greedy search is globally optimal, or model probabilities are calibrated.

Resource cap: one local process, one BLAS thread, <1 GiB planned working arrays, 300 seconds compute after download and at most 10,000 fully screened proposals per iteration. Check caps within loops. If a cap prevents exhausting the declared order, preserve a partial-result status, not a no-improvement conclusion. Commit the executable and synthetic mechanics check before the real comparison. Do not alter the live selector, run schedule, dose, contest layout or uploads.
