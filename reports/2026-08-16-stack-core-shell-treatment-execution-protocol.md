Date frozen: 2026-08-16, before the independent support census completed,
before a support anchor was known, before a treatment shard was launched, and
before any stack-core/shell treatment effect or realized score was observed.

Protocol ID: `20260816-stack-core-shell-treatment-execution-v1`.

## Release gate

The grid remains inert unless the strict support finisher has produced the
complete `20260816-stack-core-shell-control-support-census-v1` report and
completion. The launcher must bind their SHA-256 values, generations, byte
sizes, first adequate `230/220/210` anchor, positive disposition, exact source
panels and complete 54-slate/270-fold support mechanics. Caller-supplied hashes
alone are insufficient; every treatment shard and the strict finisher must
independently validate the objects and disposition.

ATLAS must also be terminally closed under its already frozen success or
failure/parity branch before this independent fallback may launch. No result
from ATLAS may change this mechanism, its resources or its gate.

## Immutable grid and canary

Use one exact source commit, one immutable image digest and one create-only
prefix for all 54 Sunday-main slates in 2023--2025. Each job reconstructs the
same five R0--R4 production-multinomial books, runs all five train-four/test-one
folds, and emits one create-only shard. Task retries remain zero.

The actual 2023 Week 1 job on the actual job name, command, prefix and output
path is the first primary execution. The remaining 53 primary cells may be
released only after that execution reaches strict terminal success, its full
execution specification matches the registered grid contract, and the output
has positive object metadata. The canary validator must not download the
object or inspect treatment effects.

Resources are fixed at 4 CPU, 16 GiB, one task, parallelism one, a four-hour
timeout and the project compute service account. A memory, timeout, signal,
solver, nonzero, cancellation, ambiguous or object-bearing failure is a
terminal scientific/infrastructure result for the population; resources are
not silently varied by cell.

## Narrow platform replacement

After all primaries are terminal, at most one separately receipted unchanged
replacement execution is allowed for a cell only when all of the following
hold:

- the terminal message is literally `Internal error running task` (optional
  terminal period and case variation only);
- succeeded count is zero, failed count is one and cancelled count is zero;
- the create-only shard object is an exact 404; and
- no memory, timeout, signal, solver, CBC, nonzero or cancellation text is
  present.

The replacement uses the existing unchanged job. Every primary and replacement
execution remains in the durable attempt ledger. Any other failure makes the
54-cell treatment population terminally invalid.

## Strict harvest and consequence

The finisher must prove that the Cloud execution set for each job equals its
receipted primary/replacement set, validate every accepted execution's exact
image, command, arguments, environment, resources, service account and terminal
success, and validate all 54 object generations/sizes before downloading any
shard. Only then may it run the frozen strict aggregator.

The report must bind the support report/completion objects, the exact 54-row
accepted execution ledger, all 270 native artifact receipts and the complete
mechanical/effect grid. A `stack-core-shell-shadow-licensed` disposition permits
only the separately frozen production-form lock and historical diagnostic. It
does not authorize a production or UI change. A failed score-free gate closes
the historical path without querying actual outcomes. No threshold, anchor,
resource, retry class, component count or selector may be changed after any
treatment shard is opened.
