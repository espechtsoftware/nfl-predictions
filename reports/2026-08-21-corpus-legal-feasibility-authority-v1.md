# Corpus legal-feasibility authority v1

Date: 2026-08-21
Status: source-green, outcome-blind science and independent replay; no launch,
historical-read, graph-write, shadow, production, or adoption authority

## Purpose

This milestone closes the deterministic science core for the larger corpus
parameter study. It does not change or reinterpret retrieval task 0. The
larger study remains a separate, default-off expansion whose launch must be
bound to an accepted immutable task-0 result receipt.

For each frozen slate task, the producer evaluates the incumbent and the six
registered relaxation arms under the same ranked R0--R4 visit schedule. It
retains every first-occurrence generated-unique roster, scores that complete
population across all 50,000 ordered source worlds, and builds an exact-80
selection. Corpus-population research remains a distinct workstream and
namespace; this retrieval/selection study cannot silently add candidates to
its own frozen inputs.

## Source and solver authority

The batch manifest, task result, and completion schemas are now v2. Every task
binds both the generation-pinned R0--R4 world-artifact receipt set and the
matching task row from the separately verified artifact-source-authority
completion. The common law binds the retained source-authority completion by
object generation, byte count, object SHA-256, and distinct internal
completion SHA-256.

`corpus_legal_feasibility.py` implements the outcome-blind producer. Each
visit uses one-thread CBC, an integer micro-DK primary objective, a frozen
player-ID rank tie-break, and a second no-good solve proving that the retained
combined optimum identifies one unique roster. The exact CBC command suffix,
terminal log line, solver binary/options, model bytes, stage evidence, elapsed
budget, attempt ledger, and zero-retry result are retained. The collision
stage keeps the original combined objective while proving infeasibility.

`corpus_legal_feasibility_verifier.py` is an independent replay path. It does
not invoke the producer's solve routine and does not read realized outcomes.
It reopens the raw authorities and reconstructs the prepared slate, registered
law, runtime effective policies, solver evidence, first-occurrence populations,
full-world score matrices, exact-80 books, paired relaxation monotonicity,
outside-incumbent-law nonvacuity, and task terminal roots. A successful replay
still records `decision_authority=false`.

## Remaining launch gates

This source milestone is not deployable by itself. Before the larger suite can
run, it still requires a default-off create-once publisher/transport/terminal
finisher, one real-artifact producer-to-independent-verifier smoke, an
accepted task-0 prerequisite receipt, an immutable image built from the exact
source commit, least-privilege runtime evidence, and the already frozen
pre-outcome/historical-read gates. Neo4j is only a rebuildable append-only
projection of accepted GCS evidence; workers cannot write it and it cannot
authorize an execution or policy adjustment.
