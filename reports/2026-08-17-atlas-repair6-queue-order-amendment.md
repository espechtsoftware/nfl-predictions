# ATLAS repair6 queue-order amendment

Frozen: 2026-08-17 after repair5 Week 7 terminated on the score-free exact
identity-tiebreak numerical boundary, while the remaining 52 post-canary jobs
were still nonterminal, before any repair5 shard body/effect or realized ATLAS
score was opened, and before the repair5 terminal census existed.

The original repair5 watcher would, after any terminally invalid population,
release the single-slate continuous-interaction parity diagnostic. That order
predated the prospectively frozen repair6 partial-function extension and would
occupy the one heavy-compute slot needed to determine whether the already
running 54-slate ATLAS program can reach a complete scoreable population.

The queue is therefore amended prospectively as follows:

1. Do not cancel, rerun or inspect any nonterminal repair5 job.
2. After all 54 repair5 primaries terminate, run the unchanged frozen repair5
   attempt classifier. If it is terminally invalid, seal the unchanged frozen
   terminal census.
3. Run the frozen repair6 failure-log classification. Any non-tiebreak failure
   closes repair6. Otherwise run only its Week 7 defect and Week 1 byte-control
   canaries, then every and only other eligible repair6 cell.
4. Strictly seal the exact repair5/repair6 hybrid population. If valid, give
   the next outcome lease to the already frozen historical-score v4 diagnostic.
5. Return the continuous-interaction parity diagnostic to the queue after the
   ATLAS historical result is strictly harvested and the outcome lease is
   released, or immediately if repair6 closes without a scoreable population.

This changes execution order only. It does not alter any repair5/repair6 model,
candidate, selector, score gate, retry rule or production policy. The choice
was made from score-free failure class and queue capacity, not from a candidate
or realized outcome.
