# Review: multi-seed candidate/world factorial implementation

Date: 2026-08-13. Review of `1e0bf04` (exact multi-seed portfolio factorial),
`43d5409` (preserve player worlds), `5a27c86` (bounded arm interaction
program), and the reconciliation of the experimental-design report.
**No code was changed. No lineup outcome was queried.**

---

## 1. Corrections I accept in full

The reconciliation raises four points against
`2026-08-13-experimental-design-arm-interactions.md`. All four are correct.

**1.1 A counting error.** The amended report says "eight marginal arms" and then
lists nine.

**1.2 The list conflates channels — the same error the report was written to
prevent.** Route Share components was primarily a **rank/copula** intervention,
because TabPFN remapping replaces the marginal for covered rows. Fitted-K is a
**within-team allocation/dependence law**. Fast-role included a
**candidate-belief generation** mechanism. Only the remaining feature/cache arms
varied player marginals.

So the report committed channel-conflation *inside the very list it used to
argue for channel declarations*. That is the same class of error twice in one
document, and the reconciliation's conclusion — **"no pooled 'eight-arm marginal
failure' conclusion is valid"** — stands. The amended report's corrected
diagnosis (most arms never improved the served upper tail) survives for the arms
that genuinely varied marginals; it may not be asserted over the whole list.

**1.3 The old Route component result cannot populate a current-stack cell.** It
predates the repaired allocation, the active-only cache lineage and the SIS
ASOE decision, and its exact-80 follow-on was an *added-candidate objective*
driven by an auxiliary 30-point probability delta — a different construction
entirely. My claim that "only the marginal-channel arm is new" was wrong: a
channel comparison on the current stack needs **both** cells run.

**1.4 Exceedance is calibration, not discrimination.** The tail table in the
amended report mixed raw exceedance rates with pinball losses as though they
were one evidence class. Raw coverage diagnoses calibration; it says nothing
about whether the model ranks correctly. Pinball is the proper score and should
carry the argument.

## 2. The implementation is a better design than the one I proposed

`ARMS = ("C0W0", "C0WU", "CUW0", "CUWU")` is a 2×2 of **candidate set × world
set**, with both factors generated by seed multiplicity rather than by a new
mechanism.

| cell | candidates | worlds |
|---|---|---|
| `C0W0` | R0 only | R0 (10,000) — the incumbent |
| `C0WU` | R0 only | R0–R4 concatenated (50,000, equal weight) |
| `CUW0` | union R0–R4 | R0 |
| `CUWU` | union R0–R4 | R0–R4 concatenated |

This is superior to the marginal × copula factorial I suggested for three
reasons: it requires no dependence mechanism to exist first, so it is available
now; it is artifact-only with no re-simulation; and it answers two independently
open questions in one run — whether the **world sample** is limiting
(`C0W0` vs `C0WU`) and whether **candidate generation** is seed-dependent
(`C0W0` vs `CUW0`).

Specific things done right:

- **Preserving player-level worlds** (`43d5409`) was the correct prerequisite
  catch. Cross-scoring a union roster in a foreign seed's worlds is impossible
  from candidate totals alone, and the explicit
  `"slate artifact lacks player worlds"` guard fails closed rather than
  silently degrading.
- Artifact identity, `cand_ix` contiguity, entry/world contract equality and
  9-unique-player roster validation are all asserted before any metric.
- Paired slate bootstrap against `C0W0` with a fixed `BOOTSTRAP_SEED` and
  2.5/97.5 quantiles is the right uncertainty construction for this design.
- A deterministic `LEAST_CHANGE_ORDER` tie-break prevents arbitrary cell
  advantage.

## 3. Three findings

### 3.1 The C factor is budget-confounded; the W factor is not

The protocol explicitly disallows a candidate cap, so `CU` holds roughly five
times the candidates of `C0`. A best-of-80 improves when drawn from a larger
pool **even with zero added diversity value**, because it is a maximum over more
draws.

This is the same added-budget pattern the CE union (12 CE / 40 boom) and role
union handled by requiring a fixed-budget follow-up before adoption, and the
precedent should apply here: **treat `CU` main effects as discovery evidence,
not as adoption evidence.**

Worth stating explicitly in the protocol, because it is favourable: **the
interaction contrast largely cancels the budget effect.** The extra candidates
appear in both `CUW0` and `CUWU`, so in

```
interaction = (CUWU − CUW0) − (C0WU − C0W0)
```

the pool-size advantage is present on both sides of the outer subtraction and
substantially nets out. Since the interaction *is* the stated scientific
question, the cleaner estimate is the one the design most cares about, and the
contaminated estimate is the `CU` main effect. Say so, so a reader does not
discount the whole factorial for a confound that mainly affects one cell
contrast.

`W` has no analogous problem. Concatenating five seeds' worlds is a variance
reduction on the same estimand, not a change of estimand — assuming the five
are independent draws from the same law, which the equal weighting asserts. So
`C0W0` vs `C0WU` is a clean measurement of whether Monte Carlo noise in the
support masks is changing the selected book, which is exactly the open question
from the Monte Carlo review.

### 3.2 The seed-variance envelope is being generated and then discarded

This is the highest-value and cheapest addition available.

Running five seeds produces exactly the material needed for the noise floor
this program has never had. But the four cells only ever use R0 standalone. The
**four other seeds' standalone books — Rᵢ candidates in Rᵢ worlds — are never
scored**, even though every artifact is already loaded and the selector already
runs.

**Recommendation: report all five per-seed standalone books alongside the four
factorial cells.** For each, the full `240/230/220/210/200/194/187` grid, mean
and median weekly best, and the mean pairwise overlap of the selected 80 across
seed pairs. Then the min–max range of each threshold count across the five.

Two reasons this matters:

1. **It is the noise floor every past adoption lacked.** Fitted-K was promoted
   on `2→3` at 240 and `2→3` at 230, with zero weeks at both on the evaluation
   panel. Whether that is signal depends entirely on a number nobody has
   measured.
2. **It gates the interpretation of this factorial.** If the five standalone
   books differ by ±2 weeks at 210, then a one-week `C0WU − C0W0` difference is
   inside seed noise and must not be read as a world-sample effect. Without the
   envelope, the factorial's own cells cannot be interpreted.

Preserve the standing constraint: this measurement is a **reported noise floor
for future comparisons**, not a licence to re-adjudicate any closed arm.

### 3.3 Report tail-specific proper scores per cell

Consistent with the reconciliation's own point 3. Alongside the threshold grid,
report q95/q99 pinball per cell — not only raw exceedance, which diagnoses
calibration but not discrimination. This is the metric discipline the amended
report should have applied to its own tail table, and it belongs in the cell
output for the same reason.

---

## 4. Summary

The implementation is sound and the design is better than what prompted it. The
prerequisite catch on player-level worlds, the fail-closed artifact guards and
the paired bootstrap are all correct.

Three amendments, in order of value:

1. **Add the five per-seed standalone books.** Near-zero marginal cost, and
   without them neither this factorial's cells nor the existing adoption record
   can be read against a noise floor.
2. **Label `CU` main effects as added-budget discovery**, and record that the
   interaction contrast largely cancels the confound — so the factorial's
   headline quantity is not compromised.
3. **Report q95/q99 pinball per cell.**

And for my own part: the reconciliation is right that the amended
experimental-design report conflated channels in its own evidence list. That
correction should be carried into the report's amendment log rather than left
only here.
