# PIT-repair revalidation scope

Frozen 2026-08-11 before rebuilding the repaired feature tables or querying
any lineup outcome produced from them.

## Purpose

The position-prior and injury-lock repairs change common historical inputs.
The TabPFN active-label finding changes one research training-label law. This
document fixes which prior conclusions must be rebuilt, which may continue
only after repair, and which remain closed. It prevents choosing the rerun set
after seeing how the repaired scores move.

An old report remains the immutable verdict for its named inputs. “Revalidate”
means it cannot remain the sole evidence for the Week-1 production path or a
downstream branch whose inputs have changed; it does not rewrite history.

## Mandatory common-data qualification

Before any repaired lineup score is queried:

1. snapshot the pre-repair row/key/schema/hash evidence required to quantify
   changes in usage, injury, vacancy, training and inference tables;
2. rebuild once from the repaired exact commit and require every static and
   dynamic PIT/universe/live-row gate to pass;
3. prove expected row/key stability, duplicate removal, source timestamp
   bounds, training/inference parity and intended feature deltas;
4. retrain every registry used by production, regenerate the canonical TabPFN
   cache from the repaired tables and verify model/cache feature contracts; and
5. repeat the complete production deployment contract and Week-1 fallback
   check before replacing the currently served digest.

No old and repaired season rows may be spliced inside one newly named panel.

## Tier 1 — mandatory Week-1 production lineage

Revalidate the following on one immutable repaired lineage with their existing
mechanisms, seeds, exact-80 requirement and tail-first law:

1. K3 versus K1 base controls. K1 may remain the base only if the repaired
   mechanical comparison still selects it.
2. The currently adopted direct-role added-budget union versus its repaired
   selected base. If its operator-policy advantage does not reproduce, choose
   the stronger mechanically valid repaired book rather than preserving the
   policy name.
3. The canonical current-label TabPFN cache and final-served diagnostics.
   The repaired historical cache is write-once
   `nfl_features.tabpfn_projections_pit_v2` under the unchanged six-season
   all-prior/non-null-label context law; both K3/K1 controls must name it
   explicitly so no stale-cache or empirical fallback can enter one arm.
4. Served-position calibration: refit the factors score-free using the same
   walk-forward grid/rule, then run one exact-80 comparison only if its original
   calibration gate passes. Old factors may not be copied onto repaired draws.
5. The complete production fallback path. A fallback that cannot be generated,
   validated and exported from the repaired registries/cache is not a fallback.

The old CE12 arm is not automatically a new scoring contest. Rebuild it only
to the extent required by the already-declared live fallback identity or if the
fixed production-lineage script mechanically reaches it after the repaired
K3/K1/role decisions.

## Tier 2 — mandatory downstream research dependencies

1. **Active-only TabPFN labels.** Generate write-once PIT-clean current-label
   and active-only caches under the unchanged respective context laws, repeat
   the identical score-free final-served gate, and release the already-frozen
   exact-80 comparison only on a clean pass. The v1 pass is superseded and no
   v1 lineup outcome may be queried.
2. **Data-fitted usage concentration.** Repeat the score-free conditional-
   likelihood fit from repaired strictly prior model shares and, only if it
   passes its unchanged gate, the same finite-K exact-80 comparison. This is
   required because the terminal fitted-K result mechanically defines the G3
   participation-hierarchy control branch.
3. **SCHED sync and team-QB cache arms.** They have not produced results. They
   start only after the repaired active-label decision and therefore need no
   separate “rerun”; their first execution simply uses the repaired lineage.
4. **G0/G1/G2/G3.** None may use a stale cache or stale fitted-K branch. Their
   existing preregistrations otherwise remain unchanged.

## Tier 3 — preserved closed arms, no automatic retry

Do not automatically rerun no-floor standalone/union, model-only blend,
ownership fade, coherent-member worlds, raw candidate scaling, alternate prop
ladder, Route final-served, Advanced Receiving, coverage or other rejected
vendor arms merely because their common baseline was rebuilt. Their sole
treatment was not the repaired position prior or injury cutoff, and both sides
shared the old common input. Reopening all losing treatments after every common
data improvement would be an outcome-driven retry loop.

A Tier-3 arm may move only through one of these outcome-blind routes:

- a previously frozen protocol explicitly requires it as a downstream control;
- the repair changes the arm's sole causal input or destroys its mechanical
  identity, documented before repaired outcomes; or
- new prospective 2026 evidence triggers a separately frozen test.

No repaired-score magnitude or attractive changed week is a reopening trigger.

## Required reporting

For every Tier-1/Tier-2 comparison report old-versus-repaired input coverage,
model/cache hashes, player served-distribution deltas, candidate/selection
overlap, threshold grid 187/194/200/210/220/230/240, weekly paired changes and
season slices. The repaired verdict governs current production/dependencies;
the old verdict remains visible and labeled with its old input provenance.

This complete scope joins the final arm ledger and exhaustion certificate in
the mandatory end-of-preseason forensic closure.
