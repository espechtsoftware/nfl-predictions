## Terminal-root contract

After all score-free work and shared-job restoration succeed, the existing
host harvester must create

`gs://nfl-predictions-503414-raw/research/recourse-aware-initial-book-runs/20260817-recourse-aware-initial-book-scorefree-v1/terminal-root.json`

with `if-generation-match=0`, then exact-reopen and byte-verify it. The root is
newline-terminated canonical JSON, self-hashed without its
`terminal_root_sha256` field, and has schema
`recourse-aware-initial-book-single-job-terminal-root-v1`.

The root binds:

1. the fixed run, Cloud Run Job name and Job UID, runtime code commit and image;
2. the exact create-once report identity and content SHA-256;
3. an ordered 54-row ledger containing every source ordinal, season/week,
   execution name, execution-metadata SHA-256, and exact shard object identity;
4. a canonical SHA-256 over that complete shard ledger;
5. SHA-256 values for harvest completion, grid terminal, canary completion,
   job restoration and final completion evidence;
6. the terminal score-free gate result, license, disposition and the laws
   `uses_realized_outcomes=false`, `production_change_licensed=false`, and
   `terminal_before_realized_outcome_read=true`.

The terminal root may be created only after local evidence is complete and
consistent. An existing unequal object, missing evidence, incomplete ledger,
wrong coordinate, failed exact reopen, or inconsistent gate is terminal.

passed score-free disposition, exact-open the report identity bound by the
root, replay its score-free contract, and prove every embedded shard's exact
canonical bytes against the root ledger. Any failure occurs before the
